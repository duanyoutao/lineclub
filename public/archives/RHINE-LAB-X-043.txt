本项目把《明日方舟》特别映像「莱茵生命：访问」中的终端界面复刻成一个可以操作的网页。它由 TypeScript、Three.js 与 Vite 构成，运行时实时渲染三维模型，不需要后端服务。档案阵列、抽取、解密、正文阅读与 360° 结构查看都按原片逐帧校准，同时保留了检索、收藏、导出与离线访问等扩展功能。

研究记录
1. 以逐帧测量代替风格模仿：开场的文字滑入、圆环轨迹与标志笔画各自保留独立的时间曲线。
2. 工程方法上保留了较强的可复核痕迹，约六十个检查脚本覆盖动效、循环、装配与画质参数。
3. 仓库地址与完整说明见 RhineLabUI (https://github.com/LBEILC/RhineLabUI)，授权范围与第三方资源边界在仓库中单独说明。

【复刻的原点】
视觉与动效参考为《明日方舟》特别映像「莱茵生命：访问」，主要取材其 5 至 40 秒的终端段落。开场不从片头开始，而是从原片 6.76 秒的白画面切入；内部结构另参考约 41 秒的正面与 46 至 51 秒的多角度画面。
复刻方式不是风格模仿，而是逐帧测量。开场左侧三行文字分别在 278、280、282 帧滑入，各自加速后减速；圆环半径、弧端、内环与橙点使用彼此独立的轨迹。这些测量结果分别保存在 boot-tracks、boot-orbit-tracks 与 boot-logo-tracks 三个模块中。
· 原片仅用于对照与验证，不随仓库分发，也不是运行依赖。
· 逐帧对照保留 1920×1080 舞台，实际交互则按真实视口铺满。

【技术构成】
界面由 TypeScript、Three.js 与 Vite 构成。运行时实时渲染三维模型，开场由 DOM 与 SVG 配合场景时间轴驱动。项目不需要后端服务，也不需要 API Key，构建产物是纯静态文件。
档案盒模型通过 Blender 制作并导出为 GLB，源工程与生成脚本一并保留在 art/ 目录，重新建模不需要改动前端代码。
· 源代码约 75 个文件、一万三千行，其中三维场景 1867 行、样式 2215 行。
· 运行所需模型为两个 GLB，分别约 3.4 MB 与 3.3 MB。
· 项目说明中记录，代码由 GPT-6 Astra 协助完成，模型通过 Blender MCP 制作。

【从阵列到档案】
主界面是五列循环档案阵列。左右切换分类列，上下翻阅同类档案，首尾相接；切回某列时保留该列上次的选择。阵列使用固定的可见窗口与外围卡片补位，因此画面不会出现队列尽头。
选中一份档案后，卡片竖直升起、镜头靠近并转向详情构图。这一过程只允许竖直升降，重构图的职责交给摄像机，以免破坏阵列原有的空间关系。
· 阵列的可见范围按实际镜头与视口动态计算，屏幕外的卡片被裁剪。
· 拖动阵列带持续惯性，松手后按实际速度滑行，接近停止时才吸附。

【解密与内构】
详情打开后，盖板由磨砂逐渐变清晰；解密线沿同一物理对角线合拢、保持，再向中央收束，采用非线性运动。右侧文档的遮挡条随之退开，逐一露出标题、资料字段与正文。
交互模式压缩了原片的时间，逐帧对照工具仍使用原时间码，两者分开维护。
· 清晰与磨砂的差异只出现在移动过程中，不保留固定高度的渐变。
· 盖板后的刻线、螺丝压槽与顶边方块都置于盖板之后，随解密一同显现。

【独立模型查看器】
详情页可以进入独立的 360° 查看器。它拥有自己的相机、平移缩放与拆解状态，并在阵列场景之外单独建立渲染管线。
模型按六组结构分层展开：紧固件、透明盖板、折射环组、光学核心、信息基板与背板框架。拆解后仍可旋转、平移与缩放，再一键重组。
· 清晰与磨砂切换不改变视角，也不会重置拆解位置。
· 进入约 320 毫秒淡入，退出约 220 毫秒淡出，退出结束后才释放模型与焦点。

【工程方法与验证】
实现过程保留了较强的可复核痕迹。视觉、相机与材质约束写在设计文档中，逐条决策与取舍记录在开发日志里，分阶段验证存放在独立的验证目录。
更少见的是检查脚本：运动、循环位置、外观、装配结构、解密轨迹、外壳、内构与画质参数各有对应的自动检查。视觉部分仍然需要在浏览器中实际查看。
· 检查脚本约六十个，覆盖动效、循环、装配与画质参数。
· 对照工具目录提供原片与复刻的叠加比较，使用前需自行准备参考视频。
