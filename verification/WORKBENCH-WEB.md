# 网页端工作台（2026-10-04）

用户要求给网页版加工作台，并明确两条约束：**不要播放模块**、**时间取本机真实时钟**。

## 复用而不是重写

工作台本体（`src/workbench.ts`、`workbench-state.ts`、`workbench-rolling.ts`、`workbench-visibility.ts`、`workbench.css`）在壁纸分支早已存在且与宿主解耦：时钟用 `new Date()`，完成状态与计时存 `localStorage["rhine-workbench-v1"]`，与阵列的模式互斥、隐藏、进场动效都由 `stage.dataset.workbench` 驱动。此前唯一的问题是整个构造被关在 `if (isWallpaper)` 里。

因此实现是「解除门禁 + 换数据源」：

- **新增 `src/workbench-source.ts`**：把宿主属性的同一袋数据从本机拼出来并**广播同一个 `rhine-wallpaper-properties` 事件**，所以两种宿主共用同一个渲染器，没有第二套工作台。
  - 条目（最多 3 条）、值守/间隙时长、七项显示开关 → `localStorage["rhine-workbench-web-v1"]`（与壁纸端的事项语义不同，故用独立键；`rhine-workbench-v1` 继续只放当天完成状态与计时）。
  - `enablemedia: false`：浏览器看不到别的应用的系统媒体会话，所以这一格**不存在**（不是灰掉）。
  - 排期：从 `content/assignments.json` 取该账号的槽位，把 `MM-DD HH:MM` **投影到下一个该日期**再交给原有的倒计时模块。设定数据保持「不随真实时钟变化」，倒计时则跟着本机时钟走。
- **`main.ts`**：两种宿主都构造工作台；网页端接上数据源、在开场选择的第三项或顶栏「▤ 工作台」进入、顶栏那个开关再切回档案展示。身份在 `completeStartup()`（登录与会话恢复的唯一汇合点）交给数据源。
- **`entry-choice.ts`**：开场选择由两项变三项（档案表 / 人员表 / 工作台）。
- **编辑入口**：条目与时长在**终端设置**里填写，工作台表面本身仍然只有「点一下打勾」这一种交互（与壁纸端一致），没有在工作台里另造一套编辑习惯。`settingsMarkup()` 在网页端渲染真实的输入项与开关；壁纸端文案不变。

两处顺带的修正：`.workbench` 的两处硬编码颜色改成 `var(--theme-*)`；`[data-workbench="true"] .system-nav > button` 的隐藏规则**豁免 `[data-workbench-flip]`**，否则进了工作台就只能钻进设置弹窗才能出来。另外底部导航的编号改为跟随**实际可用**的槽位（浏览器少一格媒体，原写法会跳号成 01 02 03 05）。

明确不搬：界面边距、HUD 曲面/鼠标追踪、自定义壁纸、桌面工作台的 WE 电源属性——这些是宿主的实验项，与浏览器无关。

### 已知缺口

- **刷新后计时继续**这一条本轮没有被探针捕捉到：脚本刷新后停在「时间日期」格，没有再去点「专注计时」格。计时用的是壁纸端同一段代码（`restoreTimer` + 绝对截止时间）与同一个存储键，条目与打勾状态已证明跨刷新保留；要单独取证需再跑一次脚本并加一步点击。
- 「没有媒体格」的证据是可见导航只有 4 项且索引为 `01 / 04`；探针里那个 `mediaLane` 字段查的是 DOM 里是否存在该按钮（隐藏的也算），因此它显示 `true`，属于探针写法问题，不代表这一格还在。
- 未在真实手机/Safari 上验证；未做逐像素设计核对。
- 工作台的开关状态不随刷新保留（壁纸端由宿主属性恢复，网页端本轮未写入续看记录）；刷新后停留在档案展示，从顶栏或开场选择再进。
